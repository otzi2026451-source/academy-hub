# Academy Hub 8.0 — закрытый хостинг: обязательные настройки владельца

## Текущий факт

GitHub Pages на `otzi2026451-source.github.io/academy-hub/` является **публичным хостингом исходных HTML/JS файлов**. Supabase Auth и RLS защищают данные, но **не скрывают статические ресурсы и URL**. Приватность репозитория GitHub не гарантирует закрытость Pages.

**В этой версии не произведён перенос на закрытый хостинг**: нет подключённого аккаунта Cloudflare/другого хостинга, домена и доступа к правилам шлюза. Не размещайте реальные персональные или служебные данные, пока эксплуатация и хранение не согласованы с уполномоченными лицами.

## Безопасный вариант

1. В аккаунте организации настройте домен или поддомен, который контролирует организация.
2. Создайте приватный хостинг, например Cloudflare Pages, и **перед выдачей адреса** настройте Cloudflare Zero Trust Access с правилом `Allow` только для утверждённых сотрудников/учётных записей. Не создавайте Allow: Everyone. Желательно обязательное MFA.
3. Исключите общедоступный origin: отключите публичный `*.pages.dev` доступ или защищайте его аналогичной политикой Access. Иначе обход защиты через другой URL остаётся возможным.
4. Перенесите только необходимые статические файлы: `index.html`, `academy*.js`, `academy*.css`, `config.js`, эмблему/графику. Не копируйте `.git`, `supabase/`, тестовые артефакты, SQL, дампы БД или секреты.
5. После проверки приватного адреса администратором **отключите публикацию GitHub Pages** в настройках GitHub: Settings → Pages → Unpublish / Source: None (вариант управления зависит от интерфейса). Публичное старое размещение нельзя оставлять как обходной путь.
6. Убедитесь, что прямой запрос приватного URL без авторизации и в приватном режиме браузера не отдаёт даже исходный HTML. Проверьте также `index.html`, `config.js`, `academy*.js`, статику и незащищённый origin.
7. Используйте отдельную учётную запись Viewer для Samsung TV; **не** оставляйте администраторский вход на публичном экране.
8. Включите блокировку утёкших паролей и MFA в Supabase Authentication, убедитесь, что все таблицы имеют RLS и что service_role/Gemini ключ остаются только на сервере. Согласуйте перечень полей для публикации и срок хранения.
9. Проведите аудит условий эксплуатации: кто имеет право хранить оценки/даты рождения, сколько они хранятся, кто может их публиковать и кому доступен телевизор.

## Что реально сделано технически

- Supabase RLS: `cadets`, `academy_grade_records` и черновики импорта закрыты.
- TV/viewer читает **проекцию** `academy_tv_board`, не полный `app_state`.
- Роли admin/editor/viewer, отзыв зарегистрированных сессий, журнал устройств.
- Предварительная серверная проверка файлов по группам и двухэтапное подтверждение записи в `cadets`.
- Тестовая схема `academy_sandbox` отделена от рабочих данных; файл `academy8-sandbox.html` полностью автономен и не обращается к Supabase.

**Не является завершённым:** подключение закрытого хостинга, реальная проверка MFA и SSO, смена DNS, выключение GitHub Pages, тест Samsung TV на физическом устройстве, подтверждение правил обработки реальных персональных данных.
