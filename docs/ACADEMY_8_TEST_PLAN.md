# Academy Hub 8.0 — контрольные сценарии

## Тесты без реальных данных

1. `academy8-sandbox.html`: 132 синтетические записи, лимиты KRD1–4 25, OTZI1 14, OTZI2 18; проверка дубликатов и превышения.
2. Supabase `academy_sandbox.cadets`: 132 фейковых записей в схеме без прав `anon/authenticated`.
3. Только администратор может выполнять `academy_sandbox_report`, `academy_prepare_roster_import`, `academy_commit_roster_import`, `academy_record_grade`.
4. Предварительный импорт: файл с повтором ФИО или кода должен быть остановлен; превышение лимита группы — остановлено; неверный ISO день рождения — остановлен.
5. Подготовка импорта возвращает `has_real_writes:false`. Только команда `academy_commit_roster_import` с текстом `IMPORT_CONFIRMED` в рамках проверенной админ-сессии создаёт реальные записи. Если `cadets` не пуст, операция отклоняется.
6. Viewer/Samsung видит экран табло, но не `cadets`, `academy_import_batches`, `academy_grade_records`; прямое чтение `app_state` для viewer запрещено.
7. TV-пинг регистрирует только идентификатор устройства, размер экрана, время и версию; не отправляет имена или баллы. Админ видит online/offline по порогу 5 минут.
8. Gemini Probe читает только метаданные доступных моделей после проверки admin JWT, без содержимого документов.
9. Все прошлые smoke-тесты: адаптивное TV 1920×1080, 1756×830, 1366×768, меню админа, три роли, редактирование недельного расписания, сохранение выбранных разделов, предпросмотр и черновики.
10. После каждого выпуска исключите секреты, персональные данные и приватные дампы из GitHub.

## Ограничения

- Автоматические Chromium-тесты используют **mock Supabase / mock Gemini**, реальный ключ Gemini и 24 часа на Samsung TV тестируются отдельно.
- Не проводится автоматическое восстановление существующей рабочей базы во избежание потери данных.
- Полная защита HTML/JS требует закрытого хостинга и отключения исходного публичного GitHub Pages.
