# Academy Hub 2.0 — телевизионное табло и импорт Word через Gemini

## Что готово
- Красивое тёмно-синее/золотое табло; `?tv=1#display` включает ТВ-режим; F11 — полный экран.
- Админ-панель Supabase Email/Password, редактирование рейтингов, расписания, дней рождения, объявлений.
- Word `.docx` и `.txt` → извлечение текста → Gemini → предварительный просмотр → выбор разделов → перенос в редактор → ручное подтверждение сохранения.
- Поддерживается прежняя таблица `public.app_state` с `id=1` и `content jsonb`. Миграция SQL НЕ НУЖНА.
- Данные обновляются каждые 15 секунд на открытом табло.

## 1. GitHub Pages — обновить сайт
1. **Сохраните текущий рабочий `config.js`** из репозитория GitHub: в нём уже есть рабочий Supabase URL и Publishable key. Файл из ZIP содержит заглушки — НЕ заменяйте рабочий `config.js` заглушками.
2. Загрузите новый `index.html` в корень того же репозитория `academy-hub` с заменой старого. Не меняйте остальные файлы. GitHub Pages обновится после публикации.
3. Если новый `config.js` нужен, скопируйте из старого рабочего файла реальные `supabaseUrl` и `supabaseAnonKey` (только publishable/anon, НИКОГДА не secret/service_role).
4. Проверьте `https://otzi2026451-source.github.io/academy-hub/` и `https://otzi2026451-source.github.io/academy-hub/?tv=1#display`.

## 2. Установить серверную функцию Gemini
Google AI Studio API key НЕ ДОЛЖЕН быть в index.html, config.js или GitHub!

В Supabase Dashboard → **Edge Functions** → **Deploy a new function** → Via Editor (или открыть функцию) → название `parse-document`.
Вставьте содержимое `supabase/functions/parse-document/index.ts` и Deploy. Если в панели есть Verify JWT, **выключите её для этой функции**: код независимо валидирует JWT у Supabase Auth через `/auth/v1/user`. Причина: новые publishable keys могут не поддерживаться старой JWT-проверкой на шлюзе. Без входа функция отказывает.

Supabase Dashboard → Edge Functions → Secrets добавьте:
- `GEMINI_API_KEY` = ключ Google AI Studio (не отправлять никому)
- `ADMIN_USER_UID` = UID **нынешнего** администратора (Authentication → Users)

`SUPABASE_URL` и `SUPABASE_ANON_KEY` обычно автоматически доступны в Edge Functions. Если нет, задайте `SUPABASE_ANON_KEY` как проектный legacy anon JWT (НЕ service_role) в секретах. Никогда не помещайте секреты в GitHub.

После создания секретов при необходимости заново разверните функцию.

## 3. Тест
1. Перейдите на опубликованный сайт → Админ-панель → Войти.
2. Создайте тестовый `.txt` файл со строками `Курсант А — 90 баллов (учёба)`, `Курсант Б — 95 баллов (учёба)`; загрузите.
3. Нажмите «Разобрать документ». Посмотрите результат и замечания Gemini.
4. Нажмите «Перенести выбранное в редактор», проверьте, затем «Сохранить на все экраны».
5. Откройте на другом Wi-Fi ТВ-режим. Проверьте изменение в течение 15 секунд.

## Примечания и безопасность
- Текущая политика RLS в Supabase позволяет публичное чтение `app_state`; не храните реальные ФИО, индивидуальные оценки или даты рождения без отдельного согласования и подходящего контроля доступа.
- Любой может открыть публичный адрес табло; админ-вкладка защищена Auth + RLS, но сам HTML админ-панели публичен (так и должно быть).
- Документ обрабатывается локально библиотекой Mammoth, но его извлечённый текст передаётся Google Gemini по серверному запросу. Не загружайте конфиденциальные документы без официального разрешения.
- ИИ может ошибаться. Всегда проверяйте значения; пустые/неизвестные категории не должны перезаписывать старые данные.
- Встроенный разбор Word требует загрузки библиотеки Mammoth с jsdelivr; для автономной работы её следует разместить локально.
- Вход в интерфейсе хранится только до перезагрузки страницы; после истечения сессии снова войдите.
